# Qudor AI — актуальное состояние проекта

Дата проверки: 13 августа 2026 года.

Qudor AI — исследовательский проект по обучению AlphaZero-агента для Quoridor 9×9. В проекте есть собственный игровой движок, кодирование состояний, policy/value ResNet, MCTS/Gumbel self-play, обучение с replay buffer, arena-gating, baseline-боты и локальный браузерный viewer.

## Текущее состояние

- Python 3.10+.
- Основные зависимости: NumPy и PyTorch.
- 35 Python-файлов, около 4241 строки Python-кода вместе с тестами и инструментами.
- 86 тестов проходят: `python -m pytest -q`.
- Синтаксическая проверка проходит: `python -m compileall -q app.py train.py quoridor_ai tests`.
- Текущая рабочая ветка содержит незакоммиченные изменения и экспериментальные файлы; они считаются частью локального состояния проекта.

## Архитектура

### Игровой движок

`quoridor_ai/core/engine.py` реализует:

- состояние доски 9×9;
- bitboard-представление горизонтальных и вертикальных стен;
- ходы пешек, прыжки и диагональные обходы;
- проверку легальности стен;
- проверку существования пути к целевой строке для обоих игроков;
- применение ходов и определение победителя.

Размер пространства действий — 209:

- 81 ход пешки;
- 64 горизонтальные стены;
- 64 вертикальные стены.

### Кодирование состояния

`quoridor_ai/core/encoding.py` поддерживает три версии:

- v1 — 11 плоскостей, обратная совместимость со старыми чекпойнтами;
- v2 — 8 плоскостей без мёртвых признаков;
- v3 — 16 плоскостей, текущая версия для новых запусков.

В v3 используются расстояния до целевой строки, число стен, занятость wall-slot, относительное представление игрока, нормализованный номер полухода и вертикальная канонизация позиции игрока 1. Для симметричного обучения также предусмотрено горизонтальное отражение.

### Нейросеть

`quoridor_ai/model.py` содержит policy/value ResNet с:

- настраиваемыми числом каналов и блоков;
- необязательными squeeze-excitation блоками;
- policy-head на 209 действий;
- value-head с выходом в диапазоне `[-1, 1]`.

Архитектура восстанавливается из весов чекпойнта. Версия кодировщика определяется по числу входных плоскостей, что предотвращает тихую загрузку модели с несовместимым входом.

### Поиск и обучение

Основной современный pipeline находится в:

- `quoridor_ai/az_selfplay.py` — self-play и MCTS-цели;
- `quoridor_ai/az_train.py` — обучение, replay buffer, EMA и сохранение;
- `quoridor_ai/az_arena.py` — сравнение кандидата с чемпионом;
- `quoridor_ai/batched_mcts.py` — пакетированный поиск;
- `quoridor_ai/baseline.py` — фиксированные baseline-боты.

Поддерживаются обычный PUCT-поиск и Gumbel AlphaZero с Gumbel-Top-k и sequential halving. Кандидат проходит arena-gating только при достижении заданного порога побед. EMA-копия сети также может участвовать в отборе.

Сохранение чекпойнтов выполняется атомарно через временный файл и `os.replace`. Продолжение обучения использует `latest.pt`; лучший подтверждённый кандидат хранится в `best.pt`. Для загрузки пользовательских чекпойнтов применяется ограниченный режим PyTorch `weights_only` в `safe_loader.py`.

## Запуск

Основной универсальный вход:

```bash
python train.py --dry-run
python train.py --output runs/az_15gb
python train.py --force-cpu
```

Конфигурации находятся в `configs/`. Для локального CPU предусмотрен `configs/local_cpu_az.json`, для Colab — `configs/colab_az_cpu.json` и `configs/colab_az_gumbel.json`. Подробный актуальный сценарий Colab находится в `RUN_COLAB_AZ.md`.

Локальный viewer:

```bash
python app.py
```

После запуска интерфейс доступен по адресу `http://127.0.0.1:8765`.

`app.py` предоставляет API для состояния игры, действий, настроек, моделей и метрик. Мутирующие запросы требуют CSRF-токен; также проверяется Origin, а путь загружаемой модели ограничен корнем проекта.

## Проверка

Быстрая проверка:

```bash
python -m compileall -q app.py train.py quoridor_ai tests
python -m pytest -q
```

Тесты покрывают движок, кодирование, модель, MCTS, self-play, arena, baseline-ботов, resume обучения и HTTP API viewer.

## Структура репозитория

- `quoridor_ai/` — основной Python-пакет;
- `quoridor_ai/core/` — правила игры и кодирование;
- `tests/` — автоматические тесты;
- `configs/` — конфигурации обучения;
- `bench/` и `tools/` — профилирование и диагностические инструменты;
- `scripts/` — локальные benchmark- и диагностические скрипты;
- `ops/cloud/` — вспомогательные cloud/server/deploy/watch-скрипты, не необходимые для работы основного Python-пакета;
- `notebooks/` — ноутбуки экспериментов;
- `legacy/` — данные и код ранних экспериментов;
- `runs/` и `local_cpu_az/` — локальные результаты и чекпойнты, не предназначенные для Git;
- `ops/` — локальные cloud/server-скрипты, исключённые из публичной публикации.

Файлы чекпойнтов (`*.pt`, `*.pth`, `*.ckpt`), логи, `runs/`, локальные эксперименты и `ops/` исключены через `.gitignore`. В репозитории пока нет lock-файла зависимостей и CI-конфигурации, поэтому для полной воспроизводимости следует дополнительно фиксировать окружение и версии PyTorch/NumPy.

## Ограничения

- Обучение существенно ограничено доступным CPU/GPU-временем и размером replay buffer.
- Встроенный HTTP-сервер предназначен для локального viewer, а не для публичного production-развёртывания.
- Legacy-модули сохранены для воспроизводимости старых экспериментов и не являются рекомендуемым новым pipeline.
- Результаты обучения зависят от конфигурации поиска, числа партий, случайного seed и статистической мощности arena-теста.

## Приоритеты развития

1. Добавить CI с установкой зависимостей, тестами и smoke-проверкой CLI.
2. Зафиксировать окружение через lock-файл или reproducibility-манифест.
3. Разделить быстрые unit-тесты и более медленные интеграционные тесты.
4. Хранить большие результаты экспериментов вне Git, оставляя manifest с метриками и параметрами запуска.
5. Добавить отдельную воспроизводимую команду оценки против baseline-ботов.
